# Spalk fork of Zitadel

This fork adds a v2 `MoveUser` API (`zitadel.user.v2.UserService/MoveUser`) that moves a human user to another organisation, keeping their ID, credentials, MFA, passkeys and IdP links. Spalk needs it because upstream Zitadel can't change a user's organisation.

It also patches the login UI (`apps/login`): a user with both a password and a linked IdP gets the password page instead of being sent straight to the IdP, and the password and passkey pages offer the organisation's active IdPs below their form. Users with only an IdP are still redirected to it. A wrong password is reported as one (with its failed-attempt count) whether the password page updates an existing session or creates a new one, and the session update's failure isn't retried as a second check. A registration started with `prompt=create` takes the login hint as its email. The changes are marked `// Spalk:` in `src/lib/server/loginname.ts`, `src/lib/server/password.ts`, `src/lib/server/cookie.ts`, `src/lib/server/flow-initiation.ts`, `src/app/(login)/password/page.tsx` and `src/app/(login)/passkey/page.tsx`.

The login UI also has a **"Keep me signed in"** checkbox (unticked by default) on the password page, the password registration and every IdP sign-in (the passkey page's prompt opens on load, so only its IdPs ask). A ticked session gets the login policy's check lifetime and its entry goes in a second, persistent `sessions_remembered` cookie that expires with it; an unticked one stays in the browser-session `sessions` cookie and lives at most `ZITADEL_LOGIN_UNREMEMBERED_SESSION_LIFETIME` (default `24h`). Reads take the union of both cookies, and writes split the entries between them. The IdP choice crosses the round trip in a one-hour `remember_me_intent` cookie. The choice is also written to the session's metadata as `spalk:remember` = `true`, which Spalk's API reads with `GetSession` on the ID token's `sid`. These changes are marked `// Spalk:` in `src/lib/cookies.ts`, `src/lib/server/cookie.ts`, `src/lib/zitadel.ts`, `src/lib/server/{password,register,idp}.ts`, `src/components/remember-me.tsx` and the forms and pages that use it.

- **Branch:** `spalk` (this fork's default branch), rebased on an upstream release tag (currently `v4.19.4`).
- **Tags and images:** `v<upstream version>-spalk.<n>`, e.g. `v4.19.4-spalk.1`. The manually run **Spalk publish image** workflow (`.github/workflows/spalk-publish.yml`) calls `.github/workflows/spalk-publish-image.yml` at a pinned commit, which builds the API image and the login UI image (from `apps/login`, as upstream's `pack.yml` does) on GitHub's arm64 runner and pushes both, tagged with the fork's tag, to Spalk's private ECR. Spalk's AWS role trusts only that file at the commits spalk-stack lists in `publish_workflow_shas`.
- **Go SDK:** [SpalkLtd/zitadel-go](https://github.com/SpalkLtd/zitadel-go) adds the `MoveUser` client.
- **Upstream workflows:** disable them in this fork's Actions settings; they need Zitadel's own runners and secrets.
- **How Spalk deploys it:** `docs/infra/zitadel-fork.md` in Spalk's monorepo.
